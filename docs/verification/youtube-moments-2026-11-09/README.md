# YouTube 시점 메모 검증 (1.9.68)

내 서재 → 유튜브 → 시점 메모, 또는 영상 막대의 시점 메모에서 사용합니다. 영상 ID·초 단위 시간과 메모를 일반 주석 레코드로 함께 보관합니다. 자막 텍스트/화면 좌표와 독립되어 자막 교체에도 보존합니다.

## 설계 검토

- **안 A · 영상별 시간순 메모 목록 (적용):** 같은 영상의 시점을 한 문서에 모으고 재생 막대에서 현재 시간을 가져옵니다. 기존 자막 기능과 동시에 사용할 수 있고 목록의 시간·연필·휴지통으로 재생·수정·삭제합니다.
- **안 B · 장면마다 독립 서재 카드:** 각 장면을 따로 찾기 쉽지만 같은 영상이 반복되고 자막 문서와 주석이 분산됩니다. 이번에는 사용자가 선택을 맡긴 범위에서 A를 적용했습니다.
- **아이콘 후보 2종:** 시계가 붙은 메모지(적용), 재생 표시가 들어간 위치 핀(대안). 둘 다 이 작업에서 직접 만든 SVG 경로입니다. [후보와 색상](design-options.svg).
- **주요 색상 후보:** 기존 선택의 슬레이트 `#334155`(적용), 차분한 청록 `#0F766E`(대안). 현재 `.codememo-design/selection.json`의 선택을 유지했고 디자인 카탈로그를 다시 생성하지 않았습니다. 앱 스타일은 기존 Tailwind CSS 4.3.3 로컬 빌드에 포함합니다.

## 확인한 범위

- 단위 1,007개 통과, 문법/JSON 246개 통과, 빌드 성공. 후속 소스 변경의 최종 CI 검증 결과를 아래 보충합니다.
- 별도 Chrome [데스크톱](desktop.json)·[320px 세로](mobile.json): 시간 링크 자동 입력, 재생 시점 고정/일시정지, 편집, 시간으로 재생, 삭제/실행 취소, 같은 영상 재사용, HTML 재가져오기, 사이드바 이동, 오류/가로 넘침 없음.
- [데스크톱 화면](desktop.png), [휴대폰 폭 입력창](mobile.png)을 직접 확인했습니다. 시점을 눌렀을 때 외부 탭까지 열리던 충돌을 실제 화면에서 발견해 재생 컨트롤을 버튼으로 바꾸고 탭이 늘지 않는 검사를 추가했습니다.
- 시험용 YouTube API 응답을 사용하는 실제 앱 UI 검사입니다. 외부 영상/광고/YouTube 네트워크 재생이나 실제 Android 기기를 검증했다는 뜻이 아닙니다. 플레이어 API는 [공식 IFrame 문서](https://developers.google.com/youtube/iframe_api_reference)의 `getCurrentTime`, `pauseVideo`, `seekTo`, `onReady` 계약을 사용합니다.
- 초기 [시점 포착 검사 실패](initial-capture-timing.json)는 시험 플레이어 준비 전에 시계를 이동한 경우였습니다. 준비 완료를 기다리도록 보완했습니다. [초기 대기 시간 초과](initial-fixture-timeout.json)와 [가로 화면 검증 서비스의 busy/quota 응답](landscape-unavailable.json)을 보존합니다. 서비스의 실패 응답을 성공으로 기록하거나 제한을 우회하지 않았으며, 가로 화면은 허용된 CI에서 검사합니다.
- 최초 전체 단위 검사 13개 실패는 격리된 사이드바 테스트 문맥에 새 `isVideoNote` 의존성을 전달하지 않은 경우였습니다. 실제 함수 주입 후 전체 1,007개를 통과했습니다.

## 보관·한계

메모는 자동 저장/이력/동기화에 포함되고, 읽기용 HTML은 안전하게 이스케이프한 메모와 시점 링크를 표시합니다. 원본 포함 `.librememo`에도 YouTube 정보·마지막 시간과 시점 메모를 보존하도록 보완했습니다. 영상 자체를 내려받거나 클립 파일로 자르지는 않습니다. 영상 재생은 인터넷과 YouTube의 외부 재생 허용이 필요합니다. 메모 작성/보관에 자막이나 확장 프로그램은 필요 없습니다.

## 게시

로컬 검증 완료. GitHub Pages 게시·공개 CI 결과 확인 후 같은 문서에 보충합니다.

1.9.68 보완: 공식 API의 `seekTo`는 cued/unstarted 상태에서 재생을 시작합니다. 메모 저장은 `cueVideoById`로 분리하고 실제 재생 클릭만 `seekTo`/`playVideo`를 사용합니다. 준비된 시간은 플레이어가 실제 재생 상태로 바뀔 때까지 유지합니다. 이 보완의 브라우저 결과는 최종 CI에서 확인하며 앞의 별도 Chrome 화면은 1.9.67 단계의 검증입니다.
