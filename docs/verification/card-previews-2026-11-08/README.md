# 카드 미리보기 확장 검증

LibreMemo 1.9.65는 내 서재의 카드가 보일 때 로컬 읽기 사본으로 미리보기를 만듭니다. PDF 첫 쪽·이미지·스크린샷·SVG 도표·문서/전자책 그림과 텍스트 본문을 사용합니다. 목록 보기·서재 밖에서는 생성 작업을 중단합니다.

- [검증 범위](validation.json): JavaScript 241개·JSON, 단위 999개, 빌드와 차이 검사 통과. 최초 최적화 검사 1개의 helper 주입 누락과 수정 결과도 기록했습니다.
- [미리보기 엔진 1280px](engine-desktop.json) · [화면](engine-desktop.png), [320px](engine-mobile.json) · [화면](engine-mobile.png): 14개 카드의 320×180 미리보기와 실제 그려진 픽셀을 확인했습니다. 모바일 가로 넘침 없음, 오류 없음, 문서 스크립트 미실행입니다.
- [실제 앱 1280px](actual-app.json) · [화면](actual-app.png): 실제 앱의 카드 관찰·생성·캐시·그리드 반영을 사용해 14개가 자동으로 채워졌습니다. 문서 탭 0개, 가로 넘침 없음, 오류 없음입니다. 임시 프로필의 OPFS 테스트 폴더를 사용했습니다.

로컬 Chrome 검사의 범위와 초기 대기 문제

[첫 변환 대기](first-worker-timeout.json), [상태 조회 대기](second-worker-timeout.json), [진행 위치](worker-diagnostic.json)를 보존합니다. 별도 검증 화면에서 DOCX 변환이 완료되지 않아 이를 통과로 세지 않았습니다. 같은 프로젝트의 실제 변환기로 Node에서 만든 Office·한글·전자책·DjVu 읽기 사본을 브라우저에 넣어 미리보기 엔진을 검사했습니다. PDF 첫 쪽과 이미지 디코딩은 Chrome에서 수행했습니다. 앱 전체의 실제 변환·목록 보기의 무읽기·주석/수정일/이력 보존·오프라인 캐시 재사용은 GitHub의 공개 Chrome 검사 결과를 이어서 기록합니다.

구현의 범위

- 서재 전체를 열지 않고 화면에 보이는 카드부터 한 개씩 처리합니다. 128개 메모리 캐시와 기기 내 영구 캐시를 사용하며, 원본 내용이 바뀌면 다시 만듭니다. 전용 폴더나 다른 기기로 캐시를 옮길 필요는 없습니다.
- 미리보기 캐시는 원본·문서 헤더·주석·북마크·수정일·저장 이력을 쓰지 않습니다. 영구 삭제 시 해당 캐시도 지웁니다. 캐시 쓰기에 실패해도 현재 화면의 미리보기와 문서 사용은 유지됩니다.
- 저장된 HTML은 앞 4MiB를 비활성 template에서 읽습니다. 원격 그림·스크립트·프레임·스타일시트를 실행하거나 다운로드하지 않습니다. SVG는 정적 그래픽만 복사하고 Office 슬라이드의 글자는 SVG 글자로 변환합니다.
- 빈 자료, 해석 한도 밖의 앞부분, 손상·암호·지원하지 않는 내용은 형식 아이콘을 유지합니다. 목록 보기는 미리보기를 위해 본문을 읽지 않습니다. 전체 로컬 브라우저 검사나 실물 휴대폰 검사 통과로 확대하지 않습니다.

게시 결과는 완료 후 보충합니다.
