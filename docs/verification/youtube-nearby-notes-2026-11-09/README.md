# 같은 폴더의 가까운 YouTube 시점 메모 (1.9.69)

내 서재 → 유튜브 → 시점 메모에서 같은 폴더의 영상을 재사용합니다. 전후 3초 이내는 기존 메모를 열며 가장 가까운 시점, 같은 거리이면 앞선 시점을 선택합니다. 링크/현재 시점으로 기존 메모를 열 때는 원래 저장된 시간을 표시하고 유지합니다. 시간 입력칸을 직접 바꾸어 편집하는 기능은 그대로입니다. 범위 밖이면 같은 영상에 새 메모를 추가하고 다른 폴더의 영상은 별도로 보관합니다.

## UI 선택

- 안 A(적용): 기존 입력창에 메모를 바로 채우고 제목·저장 버튼·안내를 편집 상태로 바꿉니다. 새 창이나 클릭을 더 요구하지 않습니다.
- 안 B: 일치하는 메모의 미리보기와 편집 버튼을 별도 확인 창으로 표시합니다. 내용을 비교하기 쉽지만 입력 단계가 늘어나므로 이번에는 적용하지 않았습니다.
- 기존에 직접 만든 아이콘 후보 두 가지(시계 메모지·재생 위치 핀)와 색상 두 가지(슬레이트 `#334155`·청록 `#0F766E`)를 [설계 자료](../youtube-moments-2026-11-09/design-options.svg)에서 검토했습니다. 현재 시계 메모지와 선택된 슬레이트를 유지합니다. `.codememo-design/selection.json`을 확인했고 카탈로그는 재생성하지 않았습니다. Tailwind CSS 4.3.3 로컬 빌드를 사용합니다.

## 검증

- `npm test` 1,014개 통과, `npm run check` JavaScript 247개와 JSON, `npm run build`, 차이 검사 통과.
- 폴더/root/휴지통 분리, ±3초 양 끝 포함, 4초 차이 제외, 가장 가까운 메모·동률 앞선 시점, 기존 ID 보존, 링크를 통한 원래 시점 유지, 초안 보존과 명시적인 시점 편집을 검사했습니다.
- 별도 신뢰된 Chrome의 [1280px](desktop.json)와 [320px](mobile.json)에서 실제 제품을 시험용 YouTube API로 실행했습니다. 폴더별 문서 2개·각 시점 메모 2개, 기존 내용 보충/ID 보존, 다른 시점 추가, 초안 복원, 입력창 가로 넘침 없음·브라우저 오류 없음을 확인했습니다. [데스크톱](desktop.png)·[모바일](mobile.png) 캡처를 직접 확인했습니다. 작은 화면은 입력창 내부 세로 스크롤로 저장 버튼에 접근합니다. 실물 기기나 실제 YouTube 스트리밍 검사는 아닙니다.
- 최초 별도 Chrome 요청은 [대기 시간 초과](initial-timeout.json)였습니다. 시험 폴더 생성 콜백의 반환 구조를 저장 API 규약에 맞추고 대기 진단 시간을 조정한 뒤 다시 확인했습니다. 해당 실패를 성공으로 기록하지 않습니다.
- 마지막 제품 변경 뒤 전체 단위/문법/빌드를 다시 통과했습니다. 로컬 전체 `npm run test:browser`나 샌드박스 내 데스크톱 Chrome은 실행하지 않았고 임시 서버는 종료했습니다.
